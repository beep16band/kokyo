# コトバの塔：問題演習ランキング（0.7.1）

ゲーム：https://beep16band.github.io/kokyo/kotoba-tower.html
教師用管理：https://beep16band.github.io/kokyo/kotoba-ranking/teacher.html

## 現在の状態

ゲーム側・教師用画面・アクセス制御の実装と、Firebaseエミュレーターでの検証は完了しています。実際のFirebaseプロジェクトの設定は未登録です。`firebase-config.json` は `enabled:false` のため、共有ランキングの送受信はまだ利用できません。通常練習とランキング用の20問挑戦は使えます。

## 初回だけ行うFirebase設定

1. https://console.firebase.google.com/ でプロジェクトを作成します。**Spark（無料）を維持し、請求先アカウントを関連付けません。** この実装ではCloud Functions・Cloud Storageを使いません。Google Analyticsも不要です。
2. プロジェクト設定からWebアプリを追加し、Web設定の **apiKey と projectId** を控えます。この2つはゲーム接続用の公開設定で、教師のパスワードやサービスアカウント秘密鍵ではありません。秘密鍵はゲームやGitHubへ置かないでください。
3. Authentication のログイン方法で **匿名**（生徒用）と **メール／パスワード**（教師用）を有効にします。教師アカウントはAuthenticationの「ユーザーを追加」から作成し、UIDを控えます。生徒はメール登録をしません。
4. Firestore Database の **Standard edition、(default) データベース**を本番モードで作成します。ルールに、このフォルダーの `firestore.rules` の全文を貼り付けて公開します。テストモードの全許可ルールにはしません。
5. Firestoreに次のドキュメントを管理画面から作ります：
   - コレクション `classes` → ドキュメント `kotoba-2026`
   - サブコレクション `teachers` → ドキュメントIDは手順3の **教師UID**
   - フィールド `active`（boolean）を `true` に設定
   `classes/kotoba-2026/teachers/教師UID` の存在が教師権限になります。生徒はこのドキュメントを作れません。親の `classes/kotoba-2026` に氏名などのフィールドは不要です。
6. リポジトリの `kotoba-ranking/firebase-config.json` を次の形式で更新します。classIdを変える場合は手順5のパスも一致させます。

```json
{
  "enabled": true,
  "apiKey": "WebアプリのapiKey",
  "projectId": "FirebaseのprojectId",
  "classId": "kotoba-2026"
}
```

apiKeyとprojectIdを開発担当へ渡せば接続設定を更新できます。教師パスワードは渡す必要がありません。Firestoreルール・教師権限はプロジェクト管理者による設定が必要です。

## 教師の利用手順

1. 教師用ページにログインします。
2. 氏名を1行1人で入力し「名簿と参加コードを作る」を押します。
3. **「教師用名簿を保存」**でJSONをダウンロードします。このJSONには氏名と秘密の参加コードが入るため、教師だけで保管します。名簿はブラウザへ自動保存しません。
4. 「参加コードをFirebaseへ登録」を押します。送信するのはランダムID・参加コード・有効状態のみで、氏名は送信しません。登録途中で通信が切れた場合も、同じ名簿で再実行できます。
5. 「問題セットをFirebaseへ登録」を押します。範囲・分野別の27セットを登録します。
6. 「配付カードを表示・印刷」し、**本人のカードだけ**を渡します。IDは出席番号と無関係です。参加コードを他人と共有しないよう伝えます。
7. 結果を確認するときは保存した教師用名簿を読み込み、条件を選んで「得点を取得」します。IDと氏名の照合は教師の端末だけで行います。氏名付きCSVも保存できます。

教員用ページのURLそのものは公開されています。URLを知っていてもFirebaseの教師権限は得られません。氏名は名簿ファイルを読み込んだ教師の端末にしかありません。教師用名簿をゲームの公開リポジトリへアップロードしないでください。

## 生徒の利用手順

1. ゲームの「問題だけ練習する」を開きます。
2. 先生の参加コードと、本名を使わないニックネームを登録します。
3. 範囲・分野を選び「ランキング挑戦を始める」を押します。
4. 最大20問を解き、解説を読み進めます。問題数が20問に満たない分野では利用可能な語句数を出題します。
5. 終了時に「この結果をランキングに送る」を押します。
6. 分野選択画面の「この条件のランキングを見る」で順位を確認します。表示は順位・ID・ニックネーム・正答数だけです。未登録の第三者はランキングを取得できません。

通常練習・冒険の戦闘はランキングへ送りません。冒険の名前入力から氏名を転用しません。時間制限はなく、最初の回答を採点します。途中終了は記録しません。同じ条件は同じ問題セットになり、最高正答数を保持、同点は同順位です（1、2、2、4）。設問・問題セットが変わると別ランキングになります。現在は固定セットの練習用ランキングです。

## 通信・引き継ぎ

- 本編と通常練習はオフラインで動きます。ランキングはGitHub公開URLとFirebaseへの通信が必要です。
- 結果送信に失敗した場合は端末へ保管し、「未送信の結果を送る」で再送します。ブラウザ保存が禁止されている場合は保管できないことを明示します。保管した本人・クラス以外へ結果を送信しません。
- 冒険JSONの形式・保存キーは変えていません。ランキングの本人登録・未送信結果は別に保存します。
- 端末を替えた場合は、同じ参加コードを登録すると同じ公開IDで送信できます。別端末の未送信結果は移りません。
- 学校のChromebookでGitHubとFirebaseへの接続、本人登録、送信、順位表示を実際に確認してから配付してください。
- 停止する参加者はFirestoreの `students/ID` の `active` を false にします。参加コードの再発行には token の更新と配付が必要です。変更前の登録は無効になります。

## 無料枠と検証の限界

Sparkで無料枠を超えた際はランキング通信が制限されます。本編は継続できます。ランキングは開いたときに取得し、常時監視しません。1回の表示は最大200人です。順位は読み取った最大200人の範囲で表示するため、この版の利用対象は1グループ200人までです。

ルールは他人への書き込み、氏名フィールド、範囲外得点、低い得点への更新を拒否します。ただしブラウザだけで採点する無料構成のため、コードを改変した本人による範囲内の虚偽得点までは検証しません。日常の演習・試用フィードバック向けです。
